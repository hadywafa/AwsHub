# 🪝 **AWS CloudFormation [Hooks?](https://docs.aws.amazon.com/cloudformation-cli/latest/hooks-userguide/what-is-cloudformation-hooks.html) – Real-Time Template Enforcement**

## 📌 What Are CloudFormation Hooks?

**CloudFormation Hooks** allow you to run **custom logic during stack operations** like `CREATE`, `UPDATE`, or `DELETE`. You can write hooks that **approve, block, or modify** CloudFormation actions **before they execute**.

✅ They work **even when users launch stacks via the AWS Console**
✅ They help enforce **security, compliance, and best practices**
✅ You can use **managed hooks** from AWS or **write your own custom hooks**

---

## 💡 How Are Hooks Different from `cfn-guard`?

| Feature                           | `cfn-guard`            | `CloudFormation Hook`                          |
| --------------------------------- | ---------------------- | ---------------------------------------------- |
| Run when?                         | Pre-deploy (manual/CI) | During stack operations (CREATE/UPDATE/DELETE) |
| Scope                             | Template validation    | Deep control of resource behavior              |
| Can block console stack creation? | ❌ No                  | ✅ Yes                                         |
| Written in                        | `.guard` rules         | Python or Java (via Lambda)                    |
| Reusable across accounts?         | ✅ Yes (rules)         | ✅ Yes (hooks via registry)                    |

---

## 🛠️ How Hooks Work

Hooks are registered with CloudFormation and **triggered automatically** during stack operations. They can be:

- 🔍 **Pre-create** (e.g., block an S3 bucket without encryption)
- 🔁 **Pre-update** (e.g., block widening a CIDR block)
- ❌ **Pre-delete** (e.g., warn if a database is about to be deleted)

---

## ✅ Real-World Use Case: Prevent Public S3 Buckets

### 🔐 Managed Hook Example

AWS provides a **managed hook** called:

> 🔐 `AWS::S3::Bucket::PreventPublicReadAccess`

You can enable it with this simple command:

```bash
aws cloudformation activate-type \
  --type HOOK \
  --type-name "AWS::S3::Bucket::PreventPublicReadAccess"
```

Then, **any new stack that tries to create a public S3 bucket will fail.** 🔥

## ✍️ Want Custom Logic? Write a Custom Hook

### 🔧 Hook Example: Block t2.micro Instance

1. Write a Python function (using the [CloudFormation CLI Hook Framework](https://docs.aws.amazon.com/cloudformation-cli/latest/userguide/hooks.html))
2. Package and register it
3. It will **auto-trigger during stack creation**

#### 🧠 Hook Logic:

```python
def pre_create_handler(session, request, callback_context):
    instance_type = request.get("desiredResourceState", {}).get("Properties", {}).get("InstanceType")
    if instance_type == "t2.micro":
        return ProgressEvent.failed("InvalidInstanceType", "t2.micro is not allowed.")
```

---

## 🚀 How to Deploy a Custom Hook

1. Install CloudFormation CLI:

   ```bash
   pip install cloudformation-cli cloudformation-cli-java-plugin cloudformation-cli-python-plugin
   ```

2. Initialize hook:

   ```bash
   cfn init --type hook
   ```

3. Write logic in `pre_create_handler`
4. Deploy to CloudFormation registry
5. Activate in your account or organization

## 🧠 Summary: When to Use What

| Goal                                     | Use                         |
| ---------------------------------------- | --------------------------- |
| Block values in console UI               | ✅ **CloudFormation Hooks** |
| Validate templates in CI/CD              | ✅ `cfn-guard`              |
| Enforce input options                    | ✅ `AllowedValues`          |
| Enforce during API + console deployments | ✅ **Hooks**                |
| Prevent public S3, wildcard IAM, etc.    | ✅ **AWS Managed Hooks**    |
