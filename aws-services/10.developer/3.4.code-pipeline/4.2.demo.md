# 🚀 Full Real-Life Example: AWS CodePipeline + CloudFormation CI/CD Pipeline

> Goal: Deploy a **Node.js web app** with full infrastructure provisioning using **AWS CodePipeline** and **CloudFormation** templates. Includes build, test, approval, and production deploy — all in one pipeline.

---

## 🧱 Project Structure

```ini
📁 my-app-repo/
├── app/
│   └── index.js
├── template/
│   ├── infra.yaml            # CloudFormation template
│   ├── config-dev.json       # Dev parameter file
│   └── config-prod.json      # Prod parameter file
├── buildspec.yml             # Build instructions for CodeBuild
└── README.md
```

---

## 🛠 Step 1: Create the CloudFormation Template (`infra.yaml`)

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Resources:
  MyLaunchTemplate:
    Type: AWS::EC2::LaunchTemplate
    Properties:
      LaunchTemplateName: my-app-template
      LaunchTemplateData:
        InstanceType: t2.micro
        ImageId: ami-1234567890abcdef0
        SecurityGroupIds:
          - sg-xxxxxxxx
        UserData:
          Fn::Base64: |
            #!/bin/bash
            cd /home/ec2-user/
            echo "Hello World" > index.html
            nohup python3 -m http.server 80 &
  MyTargetGroup:
    Type: AWS::ElasticLoadBalancingV2::TargetGroup
    Properties:
      Port: 80
      Protocol: HTTP
      VpcId: vpc-xxxxxxxx
  MyALB:
    Type: AWS::ElasticLoadBalancingV2::LoadBalancer
    Properties:
      Scheme: internet-facing
      Subnets:
        - subnet-aaaaaaa
        - subnet-bbbbbbb
  MyAutoScalingGroup:
    Type: AWS::AutoScaling::AutoScalingGroup
    Properties:
      LaunchTemplate:
        LaunchTemplateId: !Ref MyLaunchTemplate
        Version: !GetAtt MyLaunchTemplate.LatestVersionNumber
      MinSize: 1
      MaxSize: 2
      DesiredCapacity: 1
      TargetGroupARNs:
        - !Ref MyTargetGroup
```

## 🧪 Step 2: Create the Buildspec (`buildspec.yml`)

```yaml
version: 0.2
phases:
  install:
    runtime-versions:
      nodejs: 18
  build:
    commands:
      - echo "Build complete"
artifacts:
  files:
    - "**/*"
```

## 🔗 Step 4: Set Up CodePipeline

### 📦 Pipeline Stages

| Stage           | Description                                   |
| --------------- | --------------------------------------------- |
| Source          | Pull code from CodeCommit (or GitHub)         |
| Build           | Run `buildspec.yml` using CodeBuild           |
| Deploy to Dev   | CloudFormation action to create/update dev    |
| Test            | Run validation (CodeBuild/Lambda)             |
| Delete Dev      | Remove the dev stack (CloudFormation delete)  |
| Manual Approval | Wait for human input before prod deploy       |
| Deploy to Prod  | CloudFormation deploy to prod (CREATE_UPDATE) |

---

### 🛠 How to Create in Console (or CDK)

1. Create a **CodeCommit** repo and push code.
2. Create a **CodeBuild** project with the `buildspec.yml`.
3. Create a **CodePipeline** with the following actions:

#### 🔹 Deploy to Dev

- Action: CloudFormation
- Mode: Create or update stack
- Stack Name: `my-app-dev`
- Template: `template/infra.yaml`
- Parameter File: `template/config-dev.json`

#### 🔹 Delete Dev

- Action: CloudFormation
- Mode: Delete stack
- Stack Name: `my-app-dev`

#### 🔹 Deploy to Prod

- Action: CloudFormation
- Mode: Create or update stack
- Stack Name: `my-app-prod`
- Template: `template/infra.yaml`
- Parameter File: `template/config-prod.json`

## ✅ Summary Table

| Component        | Description                                    |
| ---------------- | ---------------------------------------------- |
| CloudFormation   | Manages infrastructure (EC2, ASG, ALB, etc.)   |
| CodeBuild        | Builds app (if needed)                         |
| CodePipeline     | Orchestrates the full CI/CD flow               |
| config-dev.json  | Parameter overrides for dev stack              |
| config-prod.json | Parameter overrides for prod stack             |
| Manual Approval  | Optional gate to promote changes to production |

---

💡 This pattern lets you fully automate **app + infra deployments** using Infrastructure as Code. It scales well across **multiple environments, teams, and accounts**.
