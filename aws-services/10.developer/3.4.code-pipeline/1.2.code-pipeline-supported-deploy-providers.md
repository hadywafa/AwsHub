# 🚀 **All Supported CodePipeline Deploy Providers (as of now)**

When creating a **Deploy stage** in AWS CodePipeline, you can select from a range of **deployment providers**, depending on where and how you want to deploy your application or infrastructure.

---

## 🧱 **Infrastructure Deployment Targets**

These allow you to provision and manage AWS resources:

| Provider                               | Purpose                                                 |
| -------------------------------------- | ------------------------------------------------------- |
| **AWS CloudFormation**                 | Create/Update stacks using templates (`YAML` or `JSON`) |
| **AWS CloudFormation Stack Set**       | Deploy stacks across **multiple accounts and regions**  |
| **AWS CloudFormation Stack Instances** | Deploy/update specific stack instances in a StackSet    |

---

## 🛠️ **Application Code Deployment Targets**

These handle actual application deployment to compute platforms:

| Provider                  | Use Case                                                    |
| ------------------------- | ----------------------------------------------------------- |
| **AWS CodeDeploy**        | EC2, Lambda, and ECS (In-Place or Blue/Green) deployments   |
| **AWS Elastic Beanstalk** | Deploy apps to managed environments                         |
| **AWS Lambda**            | Deploy new Lambda function versions                         |
| **Amazon EC2**            | Direct EC2 deployment using CodeDeploy                      |
| **Amazon ECS**            | Deploy containers to ECS services (standard and Blue/Green) |
| **Amazon EKS**            | Deploy container workloads to EKS clusters (new)            |
| **Amazon S3**             | Deploy static files to S3 (web apps, static websites)       |

---

## 🔧 **Configuration & Operational Targets**

| Provider                | Use Case                                                             |
| ----------------------- | -------------------------------------------------------------------- |
| **AWS AppConfig**       | Deploy configuration data to apps (feature flags, JSON config, etc.) |
| **AWS Service Catalog** | Provision pre-approved infrastructure as products                    |
| **AWS OpsWorks Stacks** | Use Chef/Puppet-based configuration management                       |

---

## 💬 **Other Specialized Targets**

| Provider             | Description                            |
| -------------------- | -------------------------------------- |
| **Alexa Skills Kit** | Deploy Alexa skills updates via Lambda |

---

## ✅ Notes:

- These options appear when configuring the **Deploy stage** in CodePipeline.
- Some targets (like **ECS Blue/Green**) need integration with **CodeDeploy**.
- Others (like **CloudFormation Stack Sets**) require additional configuration such as trusted execution roles for multi-account deployment.

---

## 🧠 Tip: Choosing the Right Deploy Provider

| If you want to...                          | Use this provider        |
| ------------------------------------------ | ------------------------ |
| Deploy to EC2, Lambda, or ECS              | AWS CodeDeploy           |
| Deploy containers to EKS                   | Amazon EKS               |
| Deploy static sites or assets              | Amazon S3                |
| Deploy infra as code with regional control | AWS CloudFormation       |
| Roll out configurations to running apps    | AWS AppConfig            |
| Provision services across accounts         | CloudFormation Stack Set |
| Push Alexa skills updates                  | Alexa Skills Kit         |
