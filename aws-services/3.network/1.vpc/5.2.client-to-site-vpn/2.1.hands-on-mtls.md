# 🌐 **AWS Client VPN with mTLS Authentication**

_Domain: `orchida-einvoice.com`_

---

## 📖 **What is mTLS Mode?**

**mTLS (Mutual TLS)** = both sides must present valid certificates signed by the same trusted **Certificate Authority (CA)**.

<div align="center" style="background-color: #141a19ff;color: #a8a5a5ff; border-radius: 10px; border: 2px solid">

| Entity                  | Example                        | Certificate Type   | Role                 |
| ----------------------- | ------------------------------ | ------------------ | -------------------- |
| AWS Client VPN Endpoint | `vpn.orchida-einvoice.com`     | Server Certificate | Identifies AWS VPN   |
| User 1                  | `client1.orchida-einvoice.com` | Client Certificate | Authenticates device |
| User 2                  | `client2.orchida-einvoice.com` | Client Certificate | Authenticates device |
| EasyRSA CA              | `OrchidaRootCA`                | Root CA            | Signs all certs      |

</div>

✅ No IAM users, no passwords — only clients with valid certs can connect.  
Ideal for small/medium teams or developer VPN access.

## ⚙️ **1. Setup EasyRSA (Your Certificate Authority)**

### 💻 Option A — Windows 11 Setup

1. **Download EasyRSA:**
   👉 [https://github.com/OpenVPN/easy-rsa/releases](https://github.com/OpenVPN/easy-rsa/releases)
   (Choose latest version like `EasyRSA-3.1.7.zip`)

2. **Extract it** to:

   ```ini
   C:\EasyRSA\
   ```

   Folder looks like:

   ```ini
   C:\EasyRSA\
   ├── EasyRSA-Start.bat
   ├── easyrsa
   ├── easyrsa.bat
   ├── vars
   ├── mksh.exe
   └── bin\
   ```

3. **Open a shell:**

   ```powershell
   cd C:\EasyRSA
   .\EasyRSA-Start.bat
   ```

   You’ll see:

   ```ini
   Note: using Easy-RSA configuration from: ./vars
   ```

---

### 🐧 Option B — Ubuntu Setup

```bash
sudo apt update
sudo apt install easy-rsa -y
mkdir ~/easy-rsa
cd ~/easy-rsa
make-cadir pki
cd pki
```

## 🔏 **2. Generate CA, Server, and Client Certificates**

Now we create certificates for your domain.

In EasyRSA shell (Windows) or Ubuntu terminal:

```bash
# Initialize the PKI
easyrsa init-pki

# Build Root CA
easyrsa build-ca nopass
# Common Name: OrchidaRootCA

# Build Server Certificate for AWS Client VPN
easyrsa build-server-full vpn.orchida-einvoice.com nopass

# Build two client certificates
easyrsa build-client-full client1.orchida-einvoice.com nopass
easyrsa build-client-full client2.orchida-einvoice.com nopass
```

---

✅ Output folder:

```ini
pki/
├── ca.crt
├── private/
│   ├── ca.key
│   ├── vpn.orchida-einvoice.com.key
│   ├── client1.orchida-einvoice.com.key
│   └── client2.orchida-einvoice.com.key
└── issued/
    ├── vpn.orchida-einvoice.com.crt
    ├── client1.orchida-einvoice.com.crt
    └── client2.orchida-einvoice.com.crt
```

> ⚠️ `ca.key` = your Root CA private key. Never upload or share it.

---

## ☁️ **3. Import Server Certificate to AWS ACM**

You’ll upload only the **server certificate** + its **private key** + the **CA chain**.

**Windows PowerShell:**

```powershell
aws acm import-certificate `
  --certificate file://pki/issued/vpn.orchida-einvoice.com.crt `
  --private-key file://pki/private/vpn.orchida-einvoice.com.key `
  --certificate-chain file://pki/ca.crt `
  --region us-east-1
```

**Ubuntu CLI:**

```bash
aws acm import-certificate \
  --certificate fileb://pki/issued/vpn.orchida-einvoice.com.crt \
  --private-key fileb://pki/private/vpn.orchida-einvoice.com.key \
  --certificate-chain fileb://pki/ca.crt \
  --region us-east-1
```

✅ Save the **Certificate ARN**, e.g.:

```ini
arn:aws:acm:us-east-1:123456789012:certificate/abcd1234efgh5678
```

---

## 🌐 **4. Create the AWS Client VPN Endpoint (mTLS Mode)**

This endpoint uses your server cert (`vpn.orchida-einvoice.com`)
and trusts the same CA (`ca.crt`) that issued your clients’ certs.

```bash
aws ec2 create-client-vpn-endpoint \
  --region us-east-1 \
  --client-cidr-block 10.250.0.0/22 \
  --server-certificate-arn arn:aws:acm:us-east-1:123456789012:certificate/abcd1234efgh5678 \
  --authentication-options Type=certificate-authentication,RootCertificateChainArn=arn:aws:acm:us-east-1:123456789012:certificate/abcd1234efgh5678 \
  --connection-log-options Enabled=true,CloudwatchLogGroup=ClientVPNLogs,CloudwatchLogStream=AuthEvents \
  --transport-protocol udp
```

✅ Note: AWS will create the endpoint ID like:

```ini
cvpn-endpoint-0a1b2c3d4e5f6g7h8
```

---

## 🏗️ **5. Associate the Endpoint with Your VPC Subnet**

```bash
aws ec2 associate-client-vpn-target-network \
  --region us-east-1 \
  --client-vpn-endpoint-id cvpn-endpoint-0a1b2c3d4e5f6g7h8 \
  --subnet-id subnet-0a12b34cd56ef78gh
```

---

## 🗺️ **6. Add Routing Rules**

### Access internal network:

```bash
aws ec2 create-client-vpn-route \
  --client-vpn-endpoint-id cvpn-endpoint-0a1b2c3d4e5f6g7h8 \
  --destination-cidr-block 10.0.0.0/16 \
  --target-vpc-subnet-id subnet-0a12b34cd56ef78gh
```

### Allow Internet egress (optional):

```bash
aws ec2 create-client-vpn-route \
  --client-vpn-endpoint-id cvpn-endpoint-0a1b2c3d4e5f6g7h8 \
  --destination-cidr-block 0.0.0.0/0 \
  --target-vpc-subnet-id subnet-0a12b34cd56ef78gh
```

---

## 🔓 **7. Add Authorization Rules**

For mTLS, no identity groups — simplest is “allow all clients”:

```bash
aws ec2 authorize-client-vpn-ingress \
  --region us-east-1 \
  --client-vpn-endpoint-id cvpn-endpoint-0a1b2c3d4e5f6g7h8 \
  --target-network-cidr 10.0.0.0/16 \
  --authorize-all-groups true
```

---

## 🧱 **8. Configure Security Groups**

Apply a Security Group to the Client VPN ENI:

- **Inbound:**

  - UDP 443 (from 0.0.0.0/0 or limited IPs)
  - All traffic from VPN CIDR `10.250.0.0/22`

- **Outbound:**

  - All traffic to 0.0.0.0/0

And ensure EC2s allow inbound from `10.250.0.0/22`.

---

## 📦 **9. Export Base Client Config File**

```bash
aws ec2 export-client-vpn-client-configuration \
  --client-vpn-endpoint-id cvpn-endpoint-0a1b2c3d4e5f6g7h8 \
  --output text > base.ovpn
```

## 💻 **11. Connect and Verify**

1. Install [AWS VPN Client](https://aws.amazon.com/vpn/client-vpn-download/)
2. Import `client1.ovpn` or `client2.ovpn`
3. Click **Connect**
4. Check:

   ```bash
   ping 10.0.1.10   # EC2 instance
   tracert 8.8.8.8  # Internet via NAT
   ```

✅ Connected clients get IPs from `10.250.0.0/22`.

## 🌍 **12. Optional: Internet via NAT Gateway (for EIP Whitelist)**

If your client portal whitelists your company’s AWS **EIP**,
configure:

- NAT Gateway with your **EIP**
- Private subnet route `0.0.0.0/0 → NAT Gateway`
- Add Client VPN route & rule `0.0.0.0/0`
  → Clients’ Internet traffic exits through that EIP.

✅ That’s the IP your client’s firewall must whitelist.

## 🧠 Quick Troubleshooting

<div align="center" style="background-color: #141a19ff;color: #a8a5a5ff; border-radius: 10px; border: 2px solid">

| Issue                      | Cause                          | Fix                                  |
| -------------------------- | ------------------------------ | ------------------------------------ |
| Cannot connect             | SG missing UDP 443             | Add inbound UDP 443                  |
| Connects but no VPC access | Route or auth rule missing     | Add both                             |
| Internet blocked           | Missing NAT or 0.0.0.0/0 route | Add NAT route                        |
| “Cert rejected”            | Wrong CA                       | Ensure client cert signed by same CA |

</div>
