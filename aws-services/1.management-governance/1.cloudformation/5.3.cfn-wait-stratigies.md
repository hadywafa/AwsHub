# 🚦 **CloudFormation Wait Strategies – The Simple Way**

## 🧠 Why Wait at All?

Sometimes, you need to **pause** a CloudFormation stack while something finishes, like:

✅ EC2 installing packages
✅ A script finishing setup
✅ Waiting for a manual approval
✅ An external system sending a green light

---

## 🎯 The Two Ways to Pause Stack Execution

| 🛠 Method              | 🔗 Waits for                          | ✅ Use When                                 |
| --------------------- | ------------------------------------- | ------------------------------------------- |
| **1. WaitCondition**  | A signal to a **pre-signed URL**      | External scripts / manual approvals         |
| **2. CreationPolicy** | A signal **from the resource itself** | EC2 instance bootstrapping / internal setup |

➡️ **Both use `cfn-signal`**, a helper tool (like `curl`) to send success or failure messages to CloudFormation.

---

## 💡 What is `cfn-signal`?

`cfn-signal` is a command-line tool that:

✅ Sends a "success" or "failure" message to CloudFormation
✅ Is easier and safer than using raw `curl`
✅ Can target either:

- A **URL** (for `WaitCondition`)
- A **resource inside the stack** (for `CreationPolicy`)

---

## ✅ Method 1: Using `WaitCondition` (with Handle + URL)

### 📌 Components:

- `WaitConditionHandle`: creates a **pre-signed URL**
- `WaitCondition`: waits for a signal to that URL
- External script (or EC2) sends the signal

### 🧱 Example YAML:

```yaml
MyWaitHandle:
  Type: AWS::CloudFormation::WaitConditionHandle

MyWaitCondition:
  Type: AWS::CloudFormation::WaitCondition
  DependsOn: MyEC2
  Properties:
    Handle: !Ref MyWaitHandle
    Timeout: "300"
    Count: 1
```

### 🧪 In EC2 or external script:

```bash
/opt/aws/bin/cfn-signal -e 0 \
  --url "https://pre-signed-url-from-MyWaitHandle"
```

🔄 This is like sending a `curl` with success message to CloudFormation’s temporary URL.

---

## ✅ Method 2: Using `CreationPolicy` (for EC2)

### 📌 Components:

- `CreationPolicy`: waits for a signal **from the resource**
- EC2 runs setup and sends signal directly

### 🧱 Example YAML:

```yaml
MyEC2:
  Type: AWS::EC2::Instance
  CreationPolicy:
    ResourceSignal:
      Count: 1
      Timeout: PT5M
  Properties:
    InstanceType: t2.micro
    ImageId: ami-12345678
    UserData:
      Fn::Base64: !Sub |
        #!/bin/bash
        yum install -y aws-cfn-bootstrap
        echo "Installing..."
        sleep 120
        /opt/aws/bin/cfn-signal -e 0 \
          --stack ${AWS::StackName} \
          --resource MyEC2 \
          --region ${AWS::Region}
```

☑️ CloudFormation waits for this resource to finish and signal “I’m done.”

---

## ⚖️ Comparison Table

| Feature                      | **WaitCondition**           | **CreationPolicy**            |
| ---------------------------- | --------------------------- | ----------------------------- |
| Signal target                | Pre-signed URL (via Handle) | Resource in the stack         |
| Good for                     | External processes          | EC2 or Auto Scaling resources |
| Needs `WaitConditionHandle`? | ✅ Yes                      | ❌ No                         |
| Needs `cfn-signal`?          | ✅ Yes                      | ✅ Yes                        |
| Timeout config location      | In `WaitCondition`          | In `CreationPolicy`           |
| Looks like `curl`?           | Yes, but safer              | Yes, but structured           |

---

## 🧠 Summary

- 🛠 Two methods: `WaitCondition` (URL-based) and `CreationPolicy` (resource-based)
- 🧩 Both use `cfn-signal` to tell CloudFormation "I'm ready"
- 🌐 `WaitConditionHandle` creates a pre-signed URL to receive the signal
- ✅ Use `CreationPolicy` for EC2 bootstrapping
- ✅ Use `WaitCondition` when an external step must finish first
